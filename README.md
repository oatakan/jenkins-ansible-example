# Optional execution-context telemetry

The provisioning play can optionally publish a small snapshot of the inventory-observed connection variables available to Ansible for each inventory host. Set `publish_execution_context: true` to enable it. When the variable is omitted or false, the play keeps its existing behavior and publishes no execution-context artifact.

The run-scoped custom-stat artifact contains `provision_execution_context`, keyed by `inventory_hostname`. Each value contains only `ansible_host` (or the inventory hostname fallback), `ansible_port` (default `22`), `ansible_connection` (default `ssh`), and `vm_uid` when that value is present and is a valid UUID string. The play rejects the deprecated `ansible_ssh_host` and `ansible_ssh_port` aliases when publication is enabled so those aliases cannot silently disagree with the published fields. SSH arguments, proxy settings, and other transport configuration are outside this report.

Ansible gathers facts before running `pre_tasks`, so this artifact is a bounded observation of the play's inventory host-variable context, not an authorization decision or proof of the transport path or network peer. Consumers must compare it with independent inventory/provider evidence. When enabled, the play rejects malformed values instead of coercing them. Validation is per host, following normal Ansible task semantics; a mixed-host failure can therefore leave observations for hosts whose validation passed. A consumer must require terminal job success and the exact expected host set before using the artifact. Host values cannot contain URL syntax, user information, or whitespace and are length-bounded. Ports must already be integers from 1 through 65535. Connection names must be simple strings of bounded length. Optional VM UIDs must already be UUID strings. No credentials, privilege-escalation data, keys, labels, or other host variables are included.
